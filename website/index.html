Six levers that cut power vs. standard ChatGPT prompts

Because generating an output token uses ~800× more energy than reading an input token, Arboris attacks both prompt bloat and unnecessary output decoding before, during, and after inference.

1. Zero-Model Local Gate−100% Wh
Intercepts pure arithmetic (12 + 7), percentages (15% of 240), and unit conversions (100 km to miles, 72 F to C) deterministically in under 1 ms — 0 GPU calls, 0 tokens, and 0 Wh.
2. Right-Sized Brevity & Stop Caps−45–70% out-tok
Standard ChatGPT replies add polite preambles and multi-paragraph recaps. Arboris routes simple lookups to Sprout (~2 sentences), explanations to Canopy (~4), and complex reasoning to Forest (~6), with expand-on-demand only when needed.
3. PromptShrink & Long-Input Pruning−32% in-tok
Strips conversational filler, email sign-offs, and wordy clauses before sending, while preserving code fences and instructions. Opt-in extractive pruning drops low-signal prose sentences on long documents.
4. Exact & Semantic Session Caching0 new tokens
Reuses verified high-quality answers across identical or lexically equivalent fact/definition queries in your session — eliminating redundant GPU prefill and decode passes completely.
5. Reasoning Effort & Small-Tier CascadeCapped CoT
Caps hidden chain-of-thought reasoning_effort on trivial queries and routes easy lookups to a smaller model tier first, escalating to the primary model only when confidence or quality score is low.
6. Output-Weighted Carbon ReceiptsTransparent
Every answer includes an interactive energy, CO₂e, and cooling-water receipt computed from provider-reported tokens (including hidden reasoning_tokens) with published academic anchors.

Routing & brevity modes

In Auto mode, Arboris selects a sentence budget and token cap before calling the model:

  • Sprout (≤12 words): ~2 sentences, 120 max tokens
  • Canopy (13–34 words): ~4 sentences, 240 max tokens
  • Forest (35+ words, complexity marker, or 2+ questions): ~6 sentences, 400 max tokens

Need a fuller explanation? Click More detail under any live answer to request an expanded Forest response.

How the numbers work

Generating tokens uses far more compute than reading prompt tokens:

  • Energy: output × 0.0006 Wh + input × 0.0006 / 800 Wh (Epoch AI 2025; Ruf & Detyniecki HotCarbon ’26)
  • Carbon: Wh / 1000 × 400 gCO₂e/kWh (0.00024 g per output token)
  • Cooling water: Wh × 0.1–0.3 mL (closed-loop data-centre WUE; generation water excluded)

All figures are arithmetic estimates from provider-reported tokens, never physical data-centre measurements.

Finland reference & limits

Clean-energy reference: Google Cloud Finland (europe-north1): ~98% carbon-free energy, 30 gCO₂eq/kWh.

Honest note: the hosted backend runs in us-central1, and OpenRouter does not disclose where upstream model inference runs. Live receipts therefore use the 400 g/kWh illustrative grid factor.

How Arboris works

Live only

Live answers on this page come from a real model through the backend: on the hosted site that backend is already running, and on your own machine it is python server/app.py. Every question goes to a real model through the backend. There is no offline fallback: if the backend is unavailable, check the backend URL in settings.

What the steps really do

  • PromptShrink runs on your actual text: it removes filler and wordy phrases and leaves code blocks alone.
  • Local arithmetic gate answers pure math expressions on the backend with 0 model tokens and 0 Wh.
  • Routing picks Sprout, Canopy or Forest from word count, complexity words, question marks, or task type (or uses the mode you explicitly select in the brevity bar).
  • Session cache reuses an earlier answer when the trimmed question and mode match one you already asked in this session.

The numbers are estimates

  • Tokens for live answers are provider-reported (including any hidden reasoning_tokens when reported). The typing preview estimates words × 1.33 before you send.
  • CO₂e is output tokens × 0.0006 Wh × 400 g CO₂e/kWh, with input tokens at 1/800 of an output token, because generating text costs far more energy than reading it. The 0.0006 Wh comes from Epoch AI's 2025 estimate for a GPT-4o-class model and the 1/800 from a 2026 measurement on smaller models. Both are assumptions here, not measurements of any data centre.
  • The baseline is assumed unless measured. Turning on Measure baseline in settings makes a second, unconstrained call per message to measure real token savings, which doubles API cost.

Privacy

This page loads no outside fonts or third-party scripts and uses no analytics. Your questions go to the backend you configured, and from there to its model provider, whose data-retention policy applies. Your chat is saved only in this browser's localStorage under arboris-live-v1; the ✕ Clear button deletes it.
